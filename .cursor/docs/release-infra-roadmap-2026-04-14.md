# DevKit 发布基础设施路线图（2026-04-14）

## 目标

围绕 Tauri 桌面分发建立可持续发布流程：自动更新、macOS 签名公证、Linux 依赖指引。

## 范围与边界

- 本阶段输出“可执行路线与检查清单”，不直接写入生产密钥或证书。
- 配置落点主要在：
  - `src-tauri/tauri.conf.json`
  - `src-tauri/Cargo.toml`
  - CI 工作流（后续新增）

## 分阶段计划

### Phase 1：发布规范化（当前可执行）

- 统一版本发布流程：前端与 Tauri 版本号对齐、变更日志模板统一。
- 明确 `bundle.targets` 对不同平台分发物的含义，减少误下载。
- README 增加平台安装前置条件与能力边界说明（已落地）。

### Phase 2：Updater 基础接入

- 为 Tauri updater 预留配置项与环境变量约定（私钥、公钥、发布源 URL）。
- 在 CI 中增加“构建 + 生成更新元数据 + 上传发布源”流水线。
- 增加回滚策略：保留上一稳定版本，支持紧急回退。

### Phase 3：macOS 签名与公证

- 证书管理：开发证书与发布证书隔离。
- CI 注入签名相关密钥（仅在发布环境可用）。
- 产物执行签名、公证与验签检查，失败即阻断发布。

### Phase 4：Linux 发行版支持矩阵

- 明确首批支持发行版（例如 Ubuntu LTS）。
- 给出运行依赖安装命令与故障排查指南（WebKitGTK/GTK）。
- 建立“最低可运行环境”验收清单。

## 风险与缓解

- 密钥泄露风险：只在 CI Secret 中注入，禁止入库。
- 多平台构建波动：引入平台独立缓存与失败重试策略。
- 依赖差异导致启动失败：维护发行版依赖矩阵并在 README 公示。

## 验收标准

- 有固定发布清单，发布过程可复现。
- 新版本可通过 updater 升级（至少一条测试通道）。
- macOS 安装不再触发未签名阻断（在目标环境验证）。
- Linux 用户按文档可完成依赖安装并成功启动。
